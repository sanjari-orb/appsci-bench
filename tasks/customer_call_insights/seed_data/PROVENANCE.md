# customer_call_insights seed data — provenance

- substrate: synthetic throughout — no real customer transcripts at any stage
- generator: none checked in; no `scripts/build_seed_data.py` exists for this task, unlike
  `order_to_cash` / `compliance_review`. Both seed_data and eval_data were produced with an LLM
  rather than a script, at different points in the project and against different
  levels of review — see below.
- license: n/a (synthetic, no external source)

## seed_data (this directory)

`fixture/transcripts.jsonl` (3 calls) + `fixture/labels.csv` — the build-time seed, loaded into the
`calls` table by `environment/db/02_load_data.py`; call ids are `seed-0001`, `seed-0002`, …

Written early in the project, **before** [`../user_sim_docs/reading_policy.md`](../user_sim_docs/reading_policy.md)
existed — LLM-generated to help guide the task's construction, then manually verified by a person and updated according with the reading_policy.md.

The `calls` table has no label column (see `../RESOURCES.md`), so **`labels.csv` is author
reference only** — it is never read by the loader or exposed to the agent.

## eval_data (`../eval_data/`, 50 calls: `cci-0056` … `cci-0105`)

Two batches, the first fully discarded and replaced by the second:

1. **First batch (discarded).** Based on [ABCD](https://github.com/asappresearch/abcd) (Action-Based
   Conversations Dataset) as source material. Dropped because its label distribution was easy for a
   dummy baseline to guess and its calls stayed narrowly on one topic — not a useful discriminator
   for this task. Its main contribution was diagnostic: the failure modes it exposed are what
   [`../GENERATION_SPEC.md`](../GENERATION_SPEC.md) was written to fix (see that file's "Why this
   rewrite is needed" section).
2. **Second batch (current, all 50 samples).** Purely synthetic, generated by an LLM against
   `../GENERATION_SPEC.md` and [`../user_sim_docs/reading_policy.md`](../user_sim_docs/reading_policy.md)
   (the label spec) over several passes, with LLM self-verification of labels throughout. A human
   spot-checked a subset of the 50 labels for correctness against reading_policy.md; the remainder
   rely on the LLM verification pass only, not a full manual review.

## Disjointness from the seed set

Distinct call-id namespace (`seed-*` vs `cci-*`) — the two sets were authored independently, do not
overlap, and neither was generated from the other.

## Reproducing

Not scripted for either set. To extend seed_data, hand-author additional `{call_id, account_id,
account_name, occurred_at, transcript}` rows in `fixture/transcripts.jsonl`, following the existing
transcript format described in `../RESOURCES.md`, and manually verify them. To extend eval_data,
follow `../GENERATION_SPEC.md` and add a new `cci-0106`-style sample per `../eval_data/README.md`,
checking it against `reading_policy.md`.
