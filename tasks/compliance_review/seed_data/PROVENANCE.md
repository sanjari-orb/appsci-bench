# compliance_review eval seed — provenance

- substrate: CUAD (Contract Understanding Atticus Dataset) v1, 510 contracts x 41 lawyer-annotated
  clause categories -- Hendrycks, Burns, Chen, Ball, "CUAD: An Expert-Annotated NLP Dataset for Legal
  Contract Review", NeurIPS 2021 Datasets & Benchmarks (arXiv:2103.06268)
- license: CC BY 4.0 (the CUAD annotations/dataset itself). The Atticus Project makes no claim on the
  underlying source contracts, which are public SEC EDGAR filings.
- source file: `CUADv1.json` from `github.com/TheAtticusProject/cuad` (`data.zip`), placed locally at
  `.ai-work/datasets/cuad/CUAD_v1/CUAD_v1.json` (gitignored -- re-downloadable, not committed)
- policies: the 4 named policies (`vendor_standard`, `ip_protective`, `risk_averse`,
  `procurement_clean`) mirror `ground-truth/compliance_v1/policies.yaml` on `a contributor/oracle-data-tooling`
  (PR #34) verbatim -- the policy is an input the artifact must handle, shared vocabulary with the
  eval, not reinvented here.

## Disjointness from the eval set (critical -- do not violate)

a contributor's `compliance_v1` eval set (PR #34) computes its gold verdicts *directly* from CUAD's
clause-presence annotations -- unlike order_to_cash, where the gold label is a derived judgment over
raw fields, here the annotation basically **is** the oracle. Exposing it at build time would hand the
agent the answer key, not just similar training data.

- `eval_holdout_contracts.txt` (this directory) is a **vendored copy** of
  `ground-truth/compliance_v1/eval_contracts.txt` as of PR #34 (48 frozen titles, `_MAX_EVAL_N = 48`
  in his `derive_oracle.py`). Must be re-synced if that file changes after the PR merges.
- `fixture/contracts.jsonl` (50 contracts) is generated by `scripts/build_seed_data.py`, which asserts
  zero overlap with `eval_holdout_contracts.txt` before writing anything, and never writes
  clause-presence/span annotations to the fixture -- only raw contract text (`contract_id`, `title`,
  `full_text`). The agent must extract clauses itself.
- `seed_data/labeled_calibration_examples.jsonl` (5 labeled dev examples; held out, not mounted to the
  agent -- see the H2 migration note in `KNOWN_ISSUES.md`) is the *one*
  place clause-presence-derived labels appear at build time, and only for contracts already confirmed
  disjoint from the eval holdout -- computed once by `build_seed_data.py` re-implementing the same
  trivial must_have/must_not_have/needs_review policy evaluation as `derive_oracle.py` (not importing
  it -- that branch is unmerged).

## Regeneration

```
python3 tasks/compliance_review/scripts/build_seed_data.py --cuad .ai-work/datasets/cuad/CUAD_v1/CUAD_v1.json
```
Deterministic given the same CUAD source + `eval_holdout_contracts.txt`: greedily selects 50
build-time-safe contracts for maximum present/absent category coverage across the 4 policies' clause
categories (currently 18/18 categories covered both ways), then takes the first 5 as labeled examples.

## TEMPORARY eval_data/ (delete once a contributor's PR #34 publishes the real one)

`tasks/compliance_review/eval_data/` and `tasks/compliance_review/eval.py` are **our own placeholder**,
not a contributor's real held-out set -- generated by `scripts/build_temp_eval_data.py`, which picks contracts
disjoint from BOTH `eval_holdout_contracts.txt` (his frozen 48) AND `seed_data/fixture/` (our own 50
build-time contracts), so they're genuinely unseen by the agent. This exists only so
`load_dataset()`/`load_objectives(resolve=True)` succeed and the build-time e2e pipeline can exercise
a real eval phase -- **scores against this set are not a trustworthy measure of task performance.**
Verified internally consistent (deterministic objectives rate their own gold 1.0 -- see
`docs/compliance_review_e2e_instructions.md`).

### Eval-time contract text is attached, not looked up

Each `eval_data/*/sample.json` attaches the contract's full text directly via
`single_turn_input.files` (a `contract.txt` sibling file, materialized by the harness's `File.materialize()`
before the artifact is queried) instead of only naming the contract by title. This matters because the
title is, by design, not in `contracts_db` at eval time -- an artifact whose only text-access path is
`SELECT full_text FROM contracts WHERE title = ?` would get nothing back for a held-out title. Flagged
by a reviewer who had hit exactly this scoring a human-baseline artifact by hand. Confirmed his real
`ground-truth/compliance_v1/derive_oracle.py::make_sample()` (PR #34) has the same title-only
instruction pattern, no `files` attachment -- its own docstring comment ("the contract document itself
is bundled at publish time, not here") says this is a known, deferred gap, not yet solved. Worth
flagging back to him that `single_turn_input.files` is the schema-native way to do it (see
`tasks/_TEMPLATE/eval_data/s1/sample.json`), since our fix here is a direct precedent.
